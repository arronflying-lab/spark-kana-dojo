# KanaDojo AGPL 发布清单

KanaDojo 上游仓库使用 `AGPL-3.0-or-later`。本文件只记录本项目的工程发布边界，不构成法律意见。

## 已采取的隔离措施

- KanaDojo 源码保留在独立下游仓库 `spark-kana-dojo`，没有把上游代码复制进星火私有门户。
- 上游来源、导入 commit、许可证和本地改动通过 `UPSTREAM.md` 与 git 历史保留。
- 星火账号、数据库服务密钥和学习数据只通过服务端适配器读取，不提交到下游仓库。
- 词汇与语法保持两个数据种类；语法不会被转换成 KanaDojo 词汇题。

## 允许进入下一阶段前必须完成

1. 在产品页或应用帮助页提供清晰的 KanaDojo 许可证、版权/来源说明和上游仓库链接。
2. 如果部署的是修改后的 KanaDojo 网络服务，为所有远程交互用户提供免费、无需特殊密码的对应源码获取入口；源码包应包含本下游仓库的完整构建、安装和运行所需代码，以及本项目对 KanaDojo 的修改。
3. 源码入口必须与实际线上版本绑定，至少保留当前部署版本对应的 commit、压缩包或可复制的源码地址；不能只链接会持续变化的 `main` 分支而无法复现线上版本。
4. 发布前检查源码包不含 Supabase service-role key、会话密钥、真实学生信息、生产环境变量或日志中的敏感数据。
5. 记录使用的第三方依赖、许可证和本地补丁；不要引入 AGPL/GPL 代码到星火私有门户，除非重新完成许可证审查。
6. 由 Aaron 在发布前确认“源码入口已上线、来源说明已上线、回滚入口可用”三个放行条件。

## 运行与回滚

- 下游部署不可被标记为“用户可用”，直到源码入口和来源说明可访问。
- 若许可证说明或源码入口异常，先关闭下游路由/访问权限，不删除学习记录或数据库数据。
- 回滚优先回到上一个已核验的 KanaDojo commit，或暂时关闭星火适配入口；不要把旧的自建闯关路由误当作新框架回滚版本。
